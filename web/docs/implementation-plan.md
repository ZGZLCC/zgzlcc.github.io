# Time 网站版执行方案

本文记录网站版的技术选型、模块边界、数据规则与验收口径。源码位于相册站点的 `web/` 目录下，构建产物复制到该站点 `dist/time/` 并发布在 <https://zgzlcc.github.io/time>，因此构建基准路径固定为 `/time/`。桌面版沿用本机另一份 Tauri + Rust 项目，不随本站发布；当前已实现的结构见 [项目结构与代码功能](project-structure.md)。

## 1. 技术选型

| 部分 | 选型 | 职责 |
| --- | --- | --- |
| 运行形态 | 纯静态站点，云端同步可选 | 由任意静态服务器或托管平台提供 `index.html` 与 `assets/` |
| 前端 | Vue 3 + TypeScript + Vite | 记录表单、打卡入口、周视图、统计与设置 |
| 业务逻辑 | `src/core/` 中的 TypeScript 纯函数 | 输入校验、重叠判定、周区间裁剪、分类时长汇总、两端合并 |
| 存储 | 浏览器 IndexedDB | 记录首先保存在当前浏览器，离线可用 |
| 云端同步 | Cloudflare Workers + KV（可选自建，支持多用户） | 保存记录的第二份副本，换设备可拉回；一个同步码一份数据 |
| 导出 | Canvas + Blob 下载、JSON 备份 | 周记录 PNG 与全量记录备份 |
| 构建 | npm + Vite，提交锁文件 | 类型检查、测试与静态产物构建 |

只使用浏览器标准能力与一个自建 Worker，不引入运行时依赖。技术依据：[Vue TypeScript](https://vuejs.org/guide/typescript/overview.html)、[IndexedDB](https://developer.mozilla.org/docs/Web/API/IndexedDB_API)、[Vite 静态部署](https://vite.dev/guide/static-deploy)、[Cloudflare D1 定价](https://developers.cloudflare.com/d1/platform/pricing/)、[Workers 限额](https://developers.cloudflare.com/workers/platform/limits/)。

## 2. 架构与模块

数据流：Vue 组件 → `src/api.ts` 门面 → `src/core/` 纯函数与 `src/storage/` 仓储 → IndexedDB →（可选）Worker → KV。

与桌面版的关键差异：桌面版由 Rust 后端承担校验与统计，网站版把同一套规则移植为 TypeScript 纯函数，业务规则仍然是唯一来源，只是运行在浏览器中；云端只承担"存一份"的职责。

```text
web/
├─ index.html                  # 页面入口，加载界面按已保存主题确定亮暗
├─ vite.config.mjs             # 相对路径 base 与构建输出配置
├─ src/
│  ├─ App.vue                  # 记录、周视图、设置三个入口与页面组合
│  ├─ api.ts                   # 组件调用的统一门面；组合纯函数与仓储
│  ├─ core/                    # 纯逻辑：校验、重叠、日期、周裁剪、分类汇总、两端合并
│  ├─ storage/                 # IndexedDB 仓储、写入串行化、同步引擎与 JSON 备份
│  ├─ features/                # records / week / settings 三个功能模块
│  └─ components/              # 跨页面复用的日期跳转控件
├─ worker/                     # 可选的 Cloudflare Worker + KV 同步后端（多用户，一个同步码一份数据）
├─ scripts/                    # 纯函数、同步合并、Worker、北京时间与构建产物检查
└─ docs/                       # 本方案、结构、部署步骤与设计规范
```

`core/` 不接触 DOM 与 IndexedDB，因此可以用 Node 直接运行测试；`storage/` 是唯一访问数据库与网络的地方，组件不直接操作存储。

## 3. 数据与时间规则

记录对象与桌面版一致：

| 字段 | 类型 | 规则 |
| --- | --- | --- |
| `id` | string | 客户端生成的 UUID；多设备离线各自新增也不会撞号 |
| `startMs`、`endMs` | number / null | UTC Unix 毫秒；草稿可为空 |
| `startDate`、`endDate` | string / null | 只选了日期、未填具体时间的草稿输入 |
| `content` | string | 草稿可为空；完成时去空白后为 1～500 字符 |
| `tag` | string / null | `work`、`leisure`、`sleep`、`other`；完成时必填 |
| `state` | string | `draft`、`completed` |
| `updatedAt` | number | 最后修改时间，同步时据此判断哪一份副本更新 |
| `deletedAt` | number / null | 删除墓碑时间；非空的记录不显示、不统计、不参与重叠判定 |

- 时间存 UTC 毫秒，输入与展示统一按北京时间 `Asia/Shanghai`（UTC+08:00），系统时区变化不影响历史记录口径。
- 一周为北京时间周一 00:00 至下周一 00:00，所有区间按左闭右开 `[start, end)` 处理，首尾相接允许保存。
- 两个时间均已填写时要求 `endMs > startMs`；手动录入精确到分钟，打卡只保留实际开始时间戳。
- 已完成记录之间禁止时间重叠，编辑时排除自身；待补全记录可暂时交叉，转为已完成时执行完整校验。
- 删除保留墓碑而不是直接抹掉行：墓碑同样参与同步比较，因此删除能单向传播，不会被另一台设备的旧数据复活；超过 180 天的墓碑在同步与导出前清理。
- IndexedDB 使用 `entries` 与 `meta` 两个对象存储，`meta` 保存本地存储创建时间；升级到 UUID 主键时重建记录表。

## 3.1 云端同步

- 目标是“第二份副本”，不是唯一来源：IndexedDB 始终是写入目标，写入成功即更新界面，云端同步失败不影响记录。
- 数据按**同步码**分区：`codes/{code}` 保存这份码是否存在、发给谁、是否被吊销，`entries/{code}` 保存该码下的全部记录，一个码一个 KV 键，天然互不干扰。
- 全部同步码的清单另存一份到 `index/codes`。**不用 KV 的 `list()` 列清单**：`list()` 是最终一致的，新建的键可能几十秒内查不到，会出现「刚建完的码立刻改备注却报找不到」；`get()` 是强一致的，所以自己维护清单。索引为空时会回退扫描一次 `codes/` 前缀把历史数据补进来，之后再走强一致路径。
- **同步码由管理员创建**：管理接口需要 `ADMIN_TOKEN`，可创建、列出与吊销；数据接口只认 `X-Time-Code` 头里的码。码是数据分区标识而非密钥（用户可在开发者工具里看到自己的码），安全性来自码足够长、只能由管理员创建、以及可随时吊销。
- 传输走 HTTPS 上的 `/api/entries`：GET 返回全部记录与修订号，POST 提交本地记录并返回合并后的全量结果。
- 冲突按记录解决：`updatedAt` 更晚者胜出，相同则保留本地副本；推送接口返回全量结果，因此客户端不会与云端分叉。
- 删除墓碑与普通记录走同一套比较规则，保证“在 A 设备删除、在 B 设备打开”不会让记录复活。
- 吊销只标记不发删除：被吊销的码立即无法读写，数据仍留在 KV 里，留出人工找回的机会。
- 防滥用：单次请求体上限 2 MB，单个同步码最多 20000 条记录，超限直接拒绝。
- CORS 默认只放行部署站点与本地开发地址，可通过 `ALLOWED_ORIGINS` 覆盖。
- Worker 只做存储边界校验（结构、大小、方法、路径）与合并写入，业务规则仍以前端 `core/` 为准，避免两套实现漂移。
- 免费额度：Workers 10 万次请求/天、KV 10 万次读/天与 **1000 次写/天**、1 GB 存储；写入是主要瓶颈，按每次同步写 2 个键算，约支持每天 500 次同步。开通与发码步骤见 [Cloudflare 部署步骤](cloudflare-setup.md)。
- **国内直连限制**：`*.workers.dev` 的 A 与 AAAA 记录都被 DNS 污染（实测解析到 Verizon 与 Meta 地址段），Cloudflare 的 IPv4 段在国内也不可达，因此不挂代理时同步必然失败，收码的人也一样。应用对此的处理是给出明确说明，并把“导出 JSON 备份”作为不依赖任何服务商的兜底。

## 4. 记录与打卡

1. 手动记录：起止日期与具体时间分开输入；选定一侧日期时另一侧默认同一天。缺时间、内容或标签时保存为待补全草稿。
2. 快速打卡：点击后取当前时间新增一条只含开始时间的待补全记录。
3. 补全记录：补齐起止时间、内容与标签后保存为已完成。
4. 待补全列表只显示起止时间，缺失位置以 `x` 占位，支持补全或居中确认删除。
5. 写操作期间禁用重复提交；同一标签页内的写操作串行执行，避免读—判—写互相穿插。
6. 记录历史默认显示全部已完成记录，标题带北京时间日期；跳转日期后只显示该日记录（跨午夜记录计入覆盖的每一天），可一键恢复全部。

## 5. 周视图与统计

- 七列日期、纵向 00:00～24:00 网格，事件块位置与高度按实际起止分钟计算，支持不足一小时的记录。
- 标签固定映射：工作蓝色 `#2563EB`、娱乐橙色 `#C2410C`、睡觉紫色 `#7C3AED`、其他灰色 `#475569`。
- 跨午夜记录按天生成显示片段，各片段关联同一原始记录；数据库只保留一条完整记录。
- 周查询按 `[weekStart, weekEnd)` 裁剪，只纳入已完成记录；单日统计取当天 `[00:00, 24:00)`，累计统计取全部已完成记录，三者共用同一套裁剪与汇总函数。
- 每条记录在本周计入 `max(0, min(endMs, weekEnd) - max(startMs, weekStart))`；按标签汇总后相加得到总时长，展示层舍去不足一分钟部分。
- 时间表下方提供 PNG 周记录图片导出：图片包含七天时间表与本周四类时长，文件名沿用 `Time_起始日期_结束日期.png`。

## 6. 设置与数据安全

- 备份导出：把全部记录连同创建时间写成带格式标识与版本号的 JSON 文件并触发下载，文件名形如 `TimeBackup_20260923_0815.json`。
- 从文件恢复：读取所选文件，校验格式标识、版本与每条记录字段，确认后整体替换本地数据；任一条记录非法则整份拒绝导入，不做部分导入。
- 清空记录：二次确认后清空 `entries` 并重置编号序列，保留存储标识。
- 本地数据卡片展示已完成与待补全条数、本地存储创建时间，并明示数据只保存在当前浏览器。
- 主题为跟随系统、亮色、暗色三个等宽按钮，选择保存在 `localStorage`，页面加载前即应用，避免闪烁。

## 7. 实施顺序与验收

| 阶段 | 实施内容 | 验收结果 |
| --- | --- | --- |
| 1. 核心逻辑 | 校验、重叠、日期与周区间、分类汇总移植为 TypeScript 纯函数 | 纯函数检查覆盖边界，类型检查通过 |
| 2. 本地存储 | IndexedDB 仓储、编号序列、写入串行化 | 新增、编辑、删除、打卡与重启后读回一致 |
| 3. 界面接入 | `api.ts` 门面与记录、周视图页面接入存储 | 记录、打卡、补全、历史跳转、周视图与统计可用 |
| 4. 备份与导出 | JSON 导出与恢复、PNG 下载、设置页改版 | 备份可导出并成功恢复，图片可按周下载 |
| 5. 静态交付 | 相对路径构建、产物检查、运行说明 | 构建产物引用完整，可直接放到静态托管目录 |
| 6. 浏览器实测 | 无头浏览器驱动真实页面走完写读链路 | 打卡、补全、重叠拦截、周视图、PNG、备份导出与恢复、刷新后保留全部通过 |
| 7. 多设备数据模型 | 记录编号改 UUID，加入 `updatedAt` 与删除墓碑 | 两端合并得到同一份数据，删除不被复活 |
| 8. 零成本云端同步 | Cloudflare Worker + KV、同步引擎与设置页同步卡片 | 推送成功、清空浏览器后重新打开自动拉回，未配置时不发请求 |
| 9. 多用户同步码 | 码换 KV 分区、管理接口与命令行工具、前端只填同步码 | 不同码数据互不可见，可创建与吊销，单码超额被拒绝 |
| 10. 直连不可用时的兜底 | 网络不可达说明、导出备份提醒与上次导出时间 | 连不上云端时说明原因且不影响记录，超过 7 天未同步或未导出会弹居中提醒 |

## 8. 验证范围

- 纯函数检查覆盖：内容去空白与 500 字边界、结束时间不晚于开始时间、无效标签与无效日期、空白输入拒绝、草稿与已完成判定、首尾相接不算重叠、编辑排除自身、重叠检查忽略草稿与已删除记录、周一与跨年周边界、跨午夜逐日片段、跨周各计时长、草稿排除、单日与累计裁剪、记录编号唯一性、修改时间比较、备份记录字段校验、两端合并与墓碑清理、网络不可达文案、同步/导出提醒阈值与导出时间读写、Worker 跨域白名单。
- Worker 检查覆盖：缺失或错误口令返回 401、未配置口令一律拒绝、未知路径与方法、预检与来源白名单、写入后可读回、旧客户端不覆盖新记录、多设备记录合并、格式非法整份拒绝。
- 构建产物检查覆盖：`dist` 入口与资源存在、全部资源为相对路径引用、产物不包含桌面版依赖且包含 IndexedDB 实现。
- 浏览器实测（`npm run test:browser`）用 Chrome DevTools Protocol 驱动无头 Edge／Chrome，在真实页面上检查：首屏与空状态渲染、打卡新增只含开始时间的待补全记录、补全后进入历史并带日期与标签、重叠记录被拒绝且保留输入与提示、IndexedDB 记录为 UUID 且带同步时间戳、备份到期提醒出现与导出后消失、周视图时间块与分类时长、周标题按北京时间周区间显示、PNG 导出为真实图片文件、暗色主题即时生效且刷新后保持、本地数据概览、地址栏 hash 同步、JSON 备份内容、清空记录、从备份文件恢复、刷新后的持久保留、把记录推送到（本地假）Worker、清空浏览器数据后重新打开自动从云端拉回。
- 假 Worker（`scripts/mock-worker.mjs`）实现与线上一致的接口与合并规则，让同步链路可以在本机完整验证，无需真实 Cloudflare 账号。
- 交付命令：`npm run verify` 执行前端与 Worker 类型检查、纯函数检查、生产构建与产物检查；`npm run test:browser` 追加浏览器实测。
