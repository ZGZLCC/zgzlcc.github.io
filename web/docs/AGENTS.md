# 开发规范与要求

本目录是 Time 的网站版（纯静态 Web）。规范沿用桌面版 `../docs/AGENTS.md` 的口径，并补充本目录特有的约定。

## 适用范围

- 开始任务前阅读本文件、[执行方案](implementation-plan.md) 和 [项目结构与代码功能](project-structure.md)。
- 界面与样式遵循 [前端设计规范](DESIGN-webflow.md)；字体不可用时使用设计文档列出的开放字体或系统回退。
- 项目发生代码、配置、目录或文档改动时，同步检查并更新 `project-structure.md`。
- 本目录是独立的静态站点：不引入服务端渲染、付费服务或需要第三方密钥的依赖；唯一的自有后端是 `worker/` 下可选的 Cloudflare Worker。

## 运行环境与依赖

- 只使用浏览器标准能力：IndexedDB 存储、Canvas 导出、Blob 下载、`File.text()` 读取、`fetch` 访问自建 Worker。
- 不引入新的运行时依赖；新增依赖前先确认标准库与现有依赖无法满足需求。
- 构建产物必须是相对路径可用的静态文件，保证既能本地打开，也能放在任意子目录部署。
- `worker/` 是可选的自建同步后端，只用 Cloudflare Workers 免费版能力（KV 绑定、Web Crypto、标准 `Request`／`Response`）；不引入 Worker 侧框架。

## 模块化与代码长度

- `src/core/` 只放纯逻辑：不访问 DOM、IndexedDB、`window`、`document`、网络，便于用 Node 直接测试。
- `src/storage/` 是唯一允许接触 IndexedDB 与网络的地方；组件不得直接操作数据库或调用远端接口。
- 单个人工维护的源码文件原则上不超过 250 行；单个函数原则上不超过 50 行。
- 复用已有实现，不为单一调用点建立抽象层。

## 数据与业务约束

- 时间存 UTC Unix 毫秒，输入与展示统一按北京时间 `Asia/Shanghai`；禁止混用秒、毫秒和无时区字符串。
- 一周固定为北京时间周一 00:00 至下周一 00:00，所有区间按左闭右开 `[start, end)` 处理。
- 已完成记录之间禁止时间重叠，编辑时排除自身；待补全记录可暂时交叉，转为已完成时再做完整校验。
- 周图、单日统计与累计统计必须共用同一套区间裁剪与汇总规则；待补全记录不得计入统计。
- 写入成功后界面才更新；失败时保留用户输入并给出可操作的中文提示。
- 记录编号使用客户端生成的 UUID；每条记录必须带 `updatedAt`，删除必须写墓碑而不是直接抹掉行。
- 同步冲突一律按记录的 `updatedAt` 取较新副本，相同则保留本地；不得引入"整份覆盖"式的合并。
- 数据以浏览器 IndexedDB 为主：云端同步失败、未配置或离线都不得影响记录与统计功能。
- 访问口令只保存在本机 localStorage 与 Worker secret 中，不得写进源码、备份文件、文档示例或提交记录。
- 不得把真实记录、个人数据、本机绝对路径或真实的 Worker 地址与口令写入源码和示例数据。

## 界面与验证

- 标签颜色与名称统一取自 `src/tags.ts`；颜色之外同时提供文字，表单有标签，按钮支持键盘操作。
- 非平凡业务逻辑至少保留一项可运行检查，覆盖真实边界（跨午夜、跨周、跨年、草稿排除、重叠）。
- 交付前执行 `npm run typecheck`、`npm run test:time` 与 `npm run build`，并在浏览器中实测记录、周视图、设置与导出。
- 文档任务检查文件位置、链接与前后一致性。

## README 要求

- 同步维护本目录 `README.md`，使用结果表述，只描述已经做成且可以验证的内容。
- 不写开发过程、进度流水账、待办列表和“已做／未做”对照；规划中的能力写入执行方案。
