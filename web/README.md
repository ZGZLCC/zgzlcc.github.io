# Time 网站版 1.0.0

Time 网站版是使用 Vue 3、TypeScript 和 Vite 构建的纯静态时间记录应用，可直接在浏览器中打开使用，不需要后端服务。记录保存在当前浏览器的 IndexedDB 中，并提供 JSON 备份导出与恢复。支持北京时间手动记录、快速打卡、草稿补全、记录编辑删除，以及跨月、跨年浏览的七天周视图和分类时长统计。

周视图按“选中日期已记录”“本周已记录”“累计记录时长”三张卡片展示工作、休闲、睡眠、其他四类时长。“选中日期已记录”跟随顶部选中的日期，标题显示该日完整日期并在今天时标注“（今天）”，跨午夜记录按落入该日的部分计入。时间块可点击或用键盘激活，并滚动到表格上方的记录详情；详情以起止时间为标题、事情内容为正文。周时间表和本周分类时长可导出为 PNG 下载。

记录历史默认显示全部已完成记录，标题带北京时间日期，最多完整显示五条、其余在卡片内滚动。历史右上角的“跳转日期”可只查看某一天的记录，跨午夜记录计入它覆盖的每一天，选择日期后可一键恢复显示全部。

设置页提供云端同步、JSON 备份导出、从文件恢复、清空记录、本地数据概览和主题选择。云端同步填入管理员发放的**同步码**，记录会在本地保存的同时同步到云端，换浏览器或换设备填入同一个码即可拉回全部记录；未填写同步码时不发出任何请求，离线也照常记录。一个同步码对应一份独立数据，由管理员在服务端创建与吊销。连接不上云端时按网络环境给出说明（`*.workers.dev` 在国内的域名解析被污染，直连必然失败），并提示本地记录不受影响。导出、恢复与清空都会使用应用自己的确认框并给出结果提示，导出文件名形如 `TimeBackup_20260923_0815.json`。主题提供跟随系统、亮色、暗色三个等宽按钮，默认跟随系统并保存选择，暗色模式覆盖记录、周视图和设置页，导出的 PNG 保持浅色便于阅读。

记录页在已有记录、且距上次同步或上次导出备份超过 7 天时弹一次居中的提醒，可直接跳到设置页导出，也可以点“明天再说”安静到次日；设置页的“本地数据”卡片同时显示上次导出备份的时间。未配置云端同步时只看导出时间，不会因为没同步而反复提醒。

## 本地运行与构建

- `npm install`：安装前端依赖。
- `npm run dev`：启动开发服务器，地址为 <http://127.0.0.1:5180/time/>。
- `npm run test:time`：北京时间转换、日期边界、按日筛选、记录校验与重叠规则、跨午夜与跨周裁剪、四类时长汇总、记录编号、同步合并与删除墓碑、Worker 鉴权与跨域白名单、网络不可达提示与备份提醒。
- `npm run build`：TypeScript 类型检查与前端生产构建，产物位于 `dist/`。
- `npm run preview`：预览已构建的 `dist/`，地址为 <http://127.0.0.1:5181/time/>。
- `npm run typecheck:worker`：检查 `worker/` 下的 Cloudflare Worker 源码类型。
- `npm run test:dist`：检查 `dist/` 的资源引用完整且都指向 `/time/`。
- `npm run test:browser`：用无头 Edge／Chrome 在真实页面上检查记录、打卡、补全、重叠提示、四类居中弹窗（备份提醒、删除、清空、恢复）的样式与居中、设置页按钮同行等宽、周视图与统计、PNG 下载、主题持久化、JSON 备份导出与恢复、云端推送与清空后自动恢复及刷新后的数据保留；需要已执行 `npm run build`，静态服务由脚本自行启停。
- `npm run verify`：依次执行前端与 Worker 类型检查、纯函数检查、生产构建与产物检查。

## 发布位置

站点为 <https://zgzlcc.github.io/time>：相册站点的 `pnpm build` 在自身构建完成后运行 `script/momo/build-web.js`，把本项目的 `dist/` 复制到 `dist/time/`，随 GitHub Pages 一起发布。因此 `vite.config.mjs` 的 `base` 固定为 `/time/`，资源以绝对路径引用，深链接与刷新都能正确加载。

## 在相册站点里调试

`astro dev` 从源码取文件、不读 `dist/`，而 `/time/` 会被相册站点的通配路由 `[...locale]/[...page].astro` 接走返回 404，所以**开发服务器上看不到本应用**。按需要选下面两种方式：

**改界面和逻辑时**（推荐，有热更新）

```bash
cd web && npm run dev        # http://127.0.0.1:5180/time/
```

**验证整站发布效果时**（与线上路径一致）

```bash
pnpm build                   # 相册与本应用一起构建，复制到 dist/time/
pnpm preview                 # http://localhost:4321/time/
```

`dist/time/` 是构建产物，改完代码必须重新构建才会更新；只想更新本应用时用 `npm run build:web`，不必重跑相册构建。云端同步在 `http://localhost:4321/time/` 下同样可用，Worker 的跨域白名单已包含相册站点的 4321/4322 端口。

## 云端同步

同步后端是 `worker/` 下自建的 Cloudflare Worker（Workers + KV 免费版）：一个**同步码**对应一份独立数据，码只能由持有管理口令的人在服务端创建、查看、停用/启用与彻底删除，因此同一个后端可以分给多个用户各自使用。

**服务地址在构建时注入**（见 `vite.config.mjs` 的 `define`，默认 `https://time-sync.zgzlcc.workers.dev`），所以用户端设置页只有一个「同步码」输入框，粘贴即可。地址不是密钥；管理口令只存在于 Cloudflare 的 secret 里，永远不进前端代码。要换地址就设环境变量 `VITE_TIME_SYNC_ENDPOINT` 重新构建，或把构建地址留空，设置页会同时显示地址输入框。

开通与管理步骤见 [Cloudflare 部署步骤](docs/cloudflare-setup.md)；不填同步码时应用完全本地运行。

## 移动端

界面按手机宽度适配到 360px：记录、周视图、设置三页在 375／390／360 三种视口下都不产生横向滚动，所有点击目标不小于 32px，设置页的操作按钮在窄屏自动换成每行两个、仍等宽铺满。这些由 `npm run test:browser` 通过 CDP 的视口模拟逐项实测，而不是靠肉眼看。

## 验证结果

纯函数检查 75 项、构建产物检查与浏览器实测 47 项均通过。浏览器实测在真实页面上走完打卡、补全、保存、重叠拦截、四类居中弹窗的样式与居中、设置页按钮同行等宽、周视图统计、PNG 下载、备份导出、清空与恢复、把记录推送到 Worker、清空浏览器数据后重新打开自动从云端恢复，重新加载页面后确认记录与主题设置仍然保留，并在 375／390／360 三种手机视口下逐页检查不横向溢出、点击目标尺寸与按钮换行。

## 数据说明

记录以 UTC Unix 毫秒保存，表单和界面按北京时间显示；一周为北京时间周一 00:00 至下周一 00:00，区间按左闭右开处理。已完成记录之间不允许时间重叠，待补全记录不计入任何统计。未配置云端同步时数据只保存在当前浏览器，清理浏览器站点数据会删除记录；配置后记录同时保存在浏览器与自建 Worker 中。
