# 财富计算器

一个零依赖的静态页面，发布在 https://zgzlcc.github.io/wealth/ ，与相册站、`/time/` 相互独立。所有计算都在浏览器里完成，不联网、不写服务端。

## 能做什么

- **工资计算**：填初始资金、年均工资、前期年数与年增长、后期年数与年增长（两段年数相加就是工作时长），页面按月推演「理财收益 + 工资 − 生活费 − 育儿 − 房贷」，看工作结束时手上还剩多少、扣掉各种预留之后能攒下多少。育儿把每孩总成本按 22 年摊到每月、每个孩子填自己的开始年份，房子先付首付、再按月付月供。工资计算排在输入表单下面，结果就在它的输入框下方。
- **这笔钱能撑多少年**：紧跟其后的第二张卡，拿上一张卡最后留下的钱，带上还没付完的育儿与房贷，按同样的收益率与通胀继续往下推，算出这些钱能支撑多少年。
- 生活开支（人均月消费、年收益率、通胀率、单人还是夫妻）与专项支出（育儿、房子、健康）在上面一起填，都是这套推演的参数。
- 参数存在本机浏览器的 localStorage（`wealth-calc-v1`）；主题分「跟随系统 / 浅色 / 深色」三选一，默认跟随系统，选择记在 `wealth-theme`，换设备不会带走。

页面算的是「工作这些年能留下多少钱」。

## 计算口径

- 金额统一按万元，比率按百分比数值（`4.5` 表示 4.5%）。
- 默认值：夫妻、人均月消费 0.5 万、年收益率 4.5%、通货膨胀率 2%、孩子 1 个（第 2 年开始）、每孩总成本 100 万、房子首付 90 万（第 8 年）+ 月供 1.1 万 × 12 × 25 年、健康预留 150 万。
- 人均月消费不含房贷与育儿，这两项在「专项支出」里单独填、单独扣。
- 育儿 = 孩子数量（向下取整到整数）× 每孩总成本；总额与从第几年开始无关，年份只决定这笔钱什么时候花。
- 房子 = 首付 + 月供 × 12 × 房贷年数；全款时把月供填 0，就只花首付。月供里含利息，所以 420 万比 300 万的房价多出来的 120 万就是这 25 年的利息。
- 工资计算的默认值：初始资金 0 万、年均工资 24 万（折合月均 2 万）、前 10 年每年涨 8%、接着 20 年每年涨 3%（合 30 年）。按这组默认值，工作结束那年手上 1,225.9 万，预留 150 万医疗之后是 1,075.9 万；另有 26.4 万房贷在工作结束后继续按月付。
- 育儿与房子的「开始年份」都从 1 数起（1 = 工作第一年，也就是第一个月就摊到 / 扣掉），填 0 或空着按第 1 年处理。育儿是每个孩子各自一个年份：改孩子数量时年份行跟着增减，新加的孩子默认第 2 年。
- 逐月的顺序：先记理财收益（月收益率 = (1 + 年收益率)^(1/12) − 1，12 个月复利正好等于年收益率），加上当月工资，再扣当月生活费（按通胀逐年上调）、育儿与房子的当月部分。工资走完一整年才调一次，两段都走完就不再涨；增长率填 0 就是工资不变，填负数就是降薪（数字框放开了后期那格，早期想填负数直接键盘输入也能算），最多降到工资 0。
- **育儿怎么摊**：22 年按年龄分六段，每段一个相对权重 —— 0–2 岁 0.6、3–5 岁（幼儿园）1.0、6–11 岁（小学）0.9、12–14 岁（初中）1.1、15–17 岁（高中）1.3、18–21 岁（大学）1.6。权重先归一化（总和 23.8），所以 22 年摊完正好等于「每孩总成本 × 孩子数」，只是前少后多。
- **育儿与月供都不随通胀调整**：两项都按填进去的名义金额固定，只有生活费按通胀逐年上涨。
- **余额转负**：只有交首付的那个月允许把余额打穿（借钱付首付）。这一段欠款不会中断推演，结果卡会写清「第几年首付时掉到多少、第几年才回到正数」；如果到最后都没转正，会说「仍在欠钱」并给出最低点。除首付之外，任何月份凭空转负都说明这套收支撑不住，推演就地停下，结果卡给出停下的月份与当时的余额。
- **这笔钱能撑多少年**：排在下面的第二张卡（没有小标题，第一行就是「这笔钱能撑」）。它拿第一张卡最后留下的钱（已扣医疗预留），从工作结束那个月接着往下推：没有工资了，生活费继续按通胀涨，没付完的育儿与房贷按各自的日程继续按月扣，余额按同一个年收益率增值，看能撑多久；收益跑得过通胀与花销时大数字直接显示「永远」，钱不够时显示 0 年。
- **末尾只留医疗**：工作结束时的余额只预留一笔医疗开销，育儿与房贷**不**在这时一次扣掉——它们会由第二张卡按月继续扣，第一张卡只会提示「还有多少育儿 / 房贷要在工作结束后继续付」。

## 本地运行

```bash
cd wealth
npm run dev     # http://127.0.0.1:5182/
npm test        # 计算、推演与结果卡文案的边界检查
```

想验证真正发布出去的形态（`/wealth/` 子目录）：

```bash
pnpm build      # 在仓库根目录执行
pnpm preview    # http://localhost:4321/wealth/
```

`astro dev` 不会提供 `/wealth/`：开发服务器只读源码，这个路径会被相册站的通配路由接走。

## 发布位置

仓库根目录的 `pnpm build` 依次执行 Astro 构建、pagefind 索引与 `script/momo/build-web.js`；后者在复制 `/time/` 之后，把本目录的 `index.html`、`icon.svg` 与 `src/` 复制到 `dist/wealth/`，随 GitHub Pages 一起上线。`test/`、`scripts/`、`package.json` 与本文档不参与部署。
